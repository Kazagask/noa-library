# V2.2 QA 与性能报告

## 测试分类

- **单元测试**：`tests/*.test.ts`，64/64 通过；覆盖协议、预算、权限、生命周期、分层、投影、baseline、跨平台契约。
- **SQLite/D1 兼容环境集成测试**：`tests/sites-d1.test.ts`、`tests/v22.test.ts`，真实 Sites Worker + node:sqlite D1 兼容层；覆盖 50 轮提交、V3 增量提交、回执索引、幂等、CAS、双世界线/双 owner、故障注入、增量 checkpoint。
- **托管 D1 验收**：未执行。缺少隔离托管数据库与凭证；不得将本地 SQLite 结果冒充托管 D1 验收。

## 故障注入

在 `noa_v3.batch` 前注入失败后：事务未落盘；重传原幂等键成功。随后模拟响应发送失败：再次重传返回原回执，revision 不推进。证据在 `tests/v22.test.ts`。

## 结论

- **通过**：历史无关读取行数保持有界（每次提交平均 7.5 行、最大 12 行），说明全量历史扫描已消除。
- **未通过**：100,000 次末段 P95 40.025ms，是 1,000 次 2.055ms 的约 19.5 倍，超过“≤2 倍”目标；主因是单个权威 state 文档随 flags 增长而变大，每次读取整份 state。
- **未通过**：托管 D1 验收未执行，不能给出真实 rows_read/rows_written、事务限制与托管性能结论。
- `event_receipt` 走索引，100,000 次后仍 0.54ms；`session_recover` 在补充 seq 索引后显著改善。

因此本轮结论是：**增量存储内核成立，但性能验收与托管 D1 验收不通过，不申请生产上线。**
